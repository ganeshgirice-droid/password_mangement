Behind the vault.

A password manager, built to make database concepts tangible.

DBMS PROJECT
iEducational demo only. Not audited, not intended to protect real-world secrets. The service is bound to localhost and stores encrypted data in a local SQLite file.
01 / PURPOSE

What this project demonstrates

VaultDB shows how a small password manager can combine relational persistence, CRUD operations, filtering, and browser-side cryptography. Sensitive fields are encrypted with AES-GCM before any API request is sent.

01 Design a clear relational schema
02 Perform create, read, update, and delete operations
03 Protect stored credential contents with encryption
04 Explain data flow and database constraints

03 / DATA MODEL

Two tables. One local vault.

The database keeps only a password-derived verifier and encrypted credential payloads. Site names, usernames, passwords, URLs, and notes are encrypted together in the browser.

Why ciphertext? The API and SQLite file never need to know the plaintext password. The encryption key is derived in the browser from the user's master password and is kept in memory only while the vault is unlocked.

06 / LIMITATIONS

Good for a classroom. Not for production.

This project is deliberately scoped as a single-user local demonstration. It does not include audited cryptographic implementation, a threat model, multi-user access control, secure backups, or production key recovery. Anyone who can run local code on your computer may be able to interfere with the app. Use dummy credentials only.
